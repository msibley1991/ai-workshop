# CLAUDE.md

Effects lab for the ai-workshop site: a sandbox for tuning a "pre-window UI" display layer (low-res emulation, glow, ghosting, scanlines/grid) with live dials. Direction lives in [../docs/aesthetic-direction.md](../docs/aesthetic-direction.md). It's a sandbox: findings feed the real site's design system, and nothing here is final.

## How it works
- The DOM in `index.html` is **invisible** (transparent text). It does layout, selection, copy and find.
- Each frame, `js/text-raster.js` redraws that layout (words, boxes, fills, SVG shapes, selection) into a low-res 2D canvas, using document coordinates measured once per layout change.
- `js/renderer.js` (three.js) composites that canvas plus the 3D object into a low-res buffer, then runs `js/passes/*`: content → ghost → blur → display.
- Effects work in **ink space**: light themes are inverted so ink is always bright on dark, then inverted back in `display.js`.

## File map
- `index.html`: specimen content. `data-ink="phosphor|accent|link|dim|ground"` sets color (`link` is the theme's link colour; CSS `text-decoration: underline` is drawn as a one-emulated-pixel line; selected text is drawn inverted, ink block with ground text) (a CSS `--ink` custom property wins, so `:hover` rules can recolor; `ground` knocks text out of a fill), `data-box` draws a border (honors CSS `border-radius` and `dashed`), `data-fill` a fill (CSS `--fill-alpha` sets its opacity; hidden fills are skipped), `svg[data-draw]` shapes are traced, `[data-graphic="<name>"]` mounts a scene graphic (`js/graphic.js`, scenes in `js/graphics/`), `img[data-draw]` images are stretched to their box and tinted with their ink, `data-tab` draws the notched Figma tab outline sized to the element (CSS `--line`, `--tab-header`, `--tab-flap` for where the notch ends, and `--tab-fill` to fill the header strip), and anything inside `data-clip` is drawn clipped to that element (nested `data-clip`s intersect). `[data-genie]` marks a text block that can genie into its panel's `[data-genie-sink]` square (`js/genie-warp.js`): while it moves, its words are drawn offscreen and warped into the frame, unclipped; genied out, they draw nothing.
- `layout.html` + `css/layout.css` + `js/layout.js`: site layout test from the Figma frames "ref1" (home, node 313:125) and "ref2" (section view, node 313:148). The intro and tabs are an accordion: scrolling scrubs between them and snaps to a whole section; clicks, keys and the URL hash (`#foundations` etc.) animate straight there. Tab headers invert on hover/focus, and the open tab's header stays inverted (its label has `aria-current`). The page is a canvas 1080 units tall scaled to the screen height (`--u` = screen px per unit, width clamped to 1440–1920 units); every length is in units, and one 12-column grid spans the canvas and is never recalculated (`--box-inset`, `--col`, `--span-N`, `.site-grid` with fixed tracks). Panels cover whole columns, and `reflow()` in `layout.js` moves each `.site-split`'s graphic and text off them: text first, down to 4 columns, then the graphic toward its scene's `span` minimum (a left nav would set `--nav-cols: 2` on `:root`). Decisions are in [../docs/design-system/layout-grid.md](../docs/design-system/layout-grid.md). The bottom bar's Grid toggle shows the columns at 25% of the phosphor ink (remembered in localStorage). Pages fire `lab:layout` on `window` to force a re-measure when layout changes without a resize (here, every animation frame). `<body data-preset="light">` loads that preset on every load; `data-panel-id` keeps its dial values separate from the specimen's. Type is fixed in CSS: Chakra Petch in the settled roles, with `@font-face` rules pointing at `../assets/fonts/` (shared with the hierarchy and type pages). The Type dials don't apply here. `<body data-viewer>` turns on the viewer controls: "Press [c] for controls" in the bottom bar opens a panel over columns 11–12 (`--controls-w` = 2 columns + inset). Opening reflows the content first, then slides the panel in while `--controls-open` and `--controls-push` stop the content boxes short of it. Closing slides it out, then reflows. It holds palette, motion, blur and scanlines, specified in [../docs/design-system/palettes.md](../docs/design-system/palettes.md). The text blocks are `data-genie` and each panel has its sink square. Tab 2 holds the placeholder slides (`js/slides.js`, below), and ← and → step the slides' beats across the whole page; the l toggle is off here. `<body data-canvas>` makes `js/main.js` treat pixelScale as units (snapped down to 1/2/4/8) and count lines in emulated pixels: the Outline dial sets `--line` (bars and tab outlines) and `--line-dashed` is one emulated pixel. Graphic slots have no frame (it was a wireframe element).
- `js/slides.js`: slides on `layout.html` (rules in [../docs/design-system/slide-templates.md](../docs/design-system/slide-templates.md)). Tab 2 holds `.slides`, with `[data-slide]` sections grouped in `[data-section]` (the name shown in `.slide-footer`, right-aligned; the footer and the panel's sink, bottom left, sit inside `.slides` so they keep the open layout, and nested `data-clip`s intersect, so the title is clipped to its tab). `data-template` is text, split (`data-split` 4 or 6), wide, row or visual, and `layoutSlide()` places the regions on the 12 columns and 6 row fields (112, 16 gutters; CSS `.slide` in `css/layout.css`), from the text axis and the covered columns, with Wide and Row statements on the base line in the bottom row fields their full text needs (`statementRows()`) and the visuals above. Each `.slide-statement > p[data-genie]` is a sentence revealed one per beat (poured out of the sink); a graphic's `data-states` lists its scene state per beat (`setGraphicState()` in `graphic.js`). A panel without slides (hero, tab 1) is one implicit slide. ← → step beats, then `change()` runs text out, then `visualSteps()` one after another: exits (old visuals fall to the panel's bottom by `translateY`, with the old section title), moves (a carried scene goes to its new box via `copyGraphicState()` and absolute left/top/width/height), entrances (new visuals rise, with the new title), then text in; between tabs the old visuals fall out and the accordion moves (400) before the new ones rise. Rapid presses `cut()` to the end state; motion off cuts. `land()` (from `settle()` in `layout.js`, unless `goPanel()` moved the accordion itself) shows a tab's first slide. The genie's spine swing mirrors when the sink is left of the block (`side` in `text-raster.js`). Graphics with `data-fit="box"` fit their box by width and height in `fit()`, hung from the top or standing on the bottom (`data-align`, or `setGraphicAlign()`, 0..1, which a carried move interpolates so the hand-over draws exactly what the old element drew). A new slide is unhidden and its entering visuals offset below the panel in the same task, so no frame draws them in place. Painting a graphic is the expensive part (CPU raster): `drawGraphic()` keeps its last two painted looks (a blink alternates without repainting) and draws flow packets over the look each frame (`packet()`), and `shade.js`'s `Raster.fill()` works in scanline spans and `interior()`/`grow()`/`silhouette()` only inside the shapes' boxes. `measure()` skips `[hidden]` subtrees. Note: the browser pane's rAF doesn't run while the pane is hidden, so probes there stand in a timer for it.
- `genie.html` + `js/genie.js` + `js/genie-warp.js` + `js/genie-play.js` + `js/genie-graphs.js` + `css/genie.css`: genie test (motion grilling session), a copy of `layout.html` with the same display layer, accordion and controls (dial values kept apart with `data-panel-id="effects-lab-genie"`). → genies the open panel's text block into its sink, an 8 × 8 ink square (`.genie-sink`, `data-genie-sink data-fill`) one box inset in from the panel's bottom-right corner, ← pours it back out, l toggles, g shows or hides the graph editor (capture-phase keys, so graphics don't also step). The block goes line by line, bottom line out first and so top line in first (line bands and the panel's sink square come from `measure()`, which reports the line count with `setLines`). The "Genie" dial panel (persisted, id `lab-genie`) is the only one open on load (the Effects Lab and Palette panels start collapsed via `DialStore.setPanelOpen`): Timing (duration in ms per line; follow, -1 all lines together, 0 one right after another, 1 a pause of one duration between; curve ease/out for each row's slide; slideStart), Funnel (edge profile p25/p50/p75 joined by Catmull-Rom; slit-scan spread within a line; row band), Spine (arc, the maximum swing in units; bends 1–4 as S-bends that are 0 at both ends; severity from rounded sine to kinked triangle), Trail (extra ghost decay while it runs, added in `main.js`), Inspect (hold + scrub, a fraction of the whole run), and "Copy values" (graphs included). The graph editor (`genie-graphs.js`, a normal visible panel bottom left) holds two bezier graphs over a line's run, each anchor `{ x, y, hin, hout }`: Arc (-1..1, scales the swing) and Narrowing (0..1.2, how far the sides have pulled in). Drag anchors and handles (handles mirror unless Shift), click the curve to add an anchor, Alt-click to remove, Reset per graph; a playhead marks the moving line's time. Graphs live in `settings.graphs` (bump `settings.graphsRev` after editing) and are saved in localStorage (`lab-genie-graphs`). Time is linear; within a line each source row runs at its own time, ahead toward the bottom, narrows and swings by the graphs and then slides down the funnel (over the funnel's last 15% the sides always close onto the square and the swing dies out), stretching to fill gaps (the slit-scan smear). `js/genie-play.js` holds the shared play logic (the open block, out / in / toggle, motion off cuts, genied-out text gets `visibility: hidden`), used by both this page and `layout.html`; the sink square's CSS is in `css/layout.css`. The defaults in `settings` are the user's tuned values (listed in motion.md). Rules are in [../docs/design-system/motion.md](../docs/design-system/motion.md).
- `type.html` + `css/type.css` + `js/type.js`: typeface specimen on the same canvas as `layout.html` (it reuses `css/layout.css`). `body[data-type]` picks a candidate, switched with keys 1–5, the bottom-bar buttons or the URL hash (`#saira-wide`, `#saira`, `#michroma-oxanium`, `#chakra`, `#michroma-chakra`) and remembered in localStorage. The rejected candidate fonts are local OFL files in `fonts/`, while Chakra Petch and JetBrains Mono come from `../assets/fonts/`. The raster honours `font-stretch` by mapping it to a canvas keyword (see [../docs/design-system/typography.md](../docs/design-system/typography.md)).
- `hierarchy.html` + `css/hierarchy.css` + `js/hierarchy.js`: type hierarchy test in Chakra Petch on the same canvas. The six roles (display, headline, statement, body, label with bar text, code) read `--r-<role>-size/-lh/-wt`, set by a second dial panel, "Type scale" (sizes limited to the spacing scale, line-heights in steps of 4). The panel's "Copy spec" copies the current values. Keys 1–4 load the presets: statement-led, tight leading, the user's tuned spec, and that spec snapped to 8, and I/S (or `#intro`/`#section`) switch between the intro and open-section views. The bottom bar shows the live spec.
- `js/shade.js`: the shading engine for code-drawn graphics. It holds the patterns (hatching, ordered and noise dither), a convex-polygon raster with per-face pattern coordinates (`Raster.fill()` in scanline spans; `interior()`, `grow()` and `silhouette()` work only inside the shapes' boxes, recorded per shape in `boxes`), the iso exploded-stack object, the drag `Spin` spring, and `ISO_STYLE`, the look tuned on the shading test (hatch density mode: 4-pixel lines every 24, 12 and 8 pixels, about 17/33/50% ink, then solid; 45°, spacing 8, width 4, 5 steps, solid top step, face-anchored, silhouette 6 grown outward plus face edges 4 centred, so the outline reads as 8 emulated pixels, ink = shadow). `js/graphic.js` builds on it.
- `js/graphic.js` + `js/graphics/*.js`: the scene engine. A scene is JS data: `kind` (`iso` or `flat`), `size` in design units, fitted to its element by `fit()`: the element is the graphic's column span, the geometry scales so the longest caption on each side ends on the span's edge (or the drawing's edge, on a side with no captions), and weights and hatching never scale; `span: [min, max]` in columns (read by the page through `graphicSpan`), iso `parts` (boxes with `explode` offsets, `origin`, `scale`) or flat `shapes` (rect, circle, convex polygon; `fill` none / solid / hatch step 1–3; `outline` outer / inner / none; `part` groups them), `connectors` (2-pixel, `dashed`, `end: "arrow"`, points in units or `{ part, point }` on an iso part), `labels` (DOM text in the label role at `at`, `side`, with a cased leader from `anchor` ending in a square dot; on an iso part, `anchor: { part }` lands on its most visible face, found from the raster, and `{ part, point }` pins it by hand; right captions start on the side's outermost `at` x (or `labelColumns.right`), left captions are left-aligned on the span's edge with each leader ending at its own caption; `hover: true` shows the label when the pointer is over its part) and `states` (`explode`, `focus` (accent), `show`, `labels`, `flow` (packets on connectors), `loop: "blink"`, `duration` 400 or 800). ← and → (`stepGraphics` from `layout.js`) step every graphic on screen with an ease-in-out tween. Rapid presses skip to the end state, and motion off (`setMotion`, from the viewer) cuts transitions, stops loops and snaps the drag back. Iso scenes drag to rotate, but not during a transition. Register a new scene in `js/graphics/index.js`. On `layout.html`: `exploded-stack` in the intro, `page-layout` in Foundations.
- `shading.html` + `css/shading.css` + `js/shading.js`: shading test, dither vs hatching side by side (graphics grilling session). It uses `js/shade.js`. Standalone: its own two-colour low-res canvas (palette ground + ink from `presets/palettes.json`), not the raster or display passes. Each column has a step ramp, a flat diagram and an isometric exploded stack (software-projected, drag to rotate, critically damped spring back to the iso pose). The "Shading" dial panel (persisted, id `lab-shading`) sets palette, emulated pixel, pattern anchor (faces or screen), edges, what ink means (shadow or light, auto by ground), light direction, the dither pattern (Bayer 2/4/8, halftone, line screen, white/blue noise, interleaved gradient, Floyd–Steinberg, Atkinson) and scale, the hatching mode (coverage, density, cross, weight), angle, spacing and width, and each side's steps and lightest/darkest range.
- `css/text-layer.css`: layout of the invisible DOM; type sizes are CSS variables set from the dials.
- `js/params.js`: **all** dial definitions and defaults (including `warp`, the rolling CRT/tape wave applied in `passes/display.js`). Add new parameters here first.
- `js/panel.js`: dialkit panel and preset actions. `js/scroll.js`: snapped render offset and scroll velocity.
- `js/viewer.js`: viewer controls state (palette choice, motion, blur, scanlines), remembered in localStorage. Motion, blur and scanlines are applied as render overrides by `applyViewer()` in `main.js`. Only pages with `data-viewer` are affected.
- `js/palette-panel.js` + `presets/palettes.json`: the "Palette" dial panel on viewer pages. It edits the active palette (ground, ink, accent, link, ghost 1–3; light or dark follows the ground via `modeOf()`), writes it into the effects dials (theme `phosphor` = ink) once the pinned preset has loaded (`kit.ready`), and its "Save palettes" action writes `presets/palettes.json`.
- `js/main.js`: frame loop.
- `presets/*.json`: named presets (partial values are fine). Add the file name to `presets.file` options in `js/params.js`. The panel's "Save to preset" overwrites the selected preset file with the current dials (needs `serve.py`, which accepts that PUT from this machine only).
- `vendor/dialkit/`: vendored dialkit 2.1.0 (plain-JS build). three.js loads from jsdelivr via the import map.

## Conventions
- Plain HTML + ES modules, no build step. Serve the repo root with `python3 serve.py` (port 8123, no browser caching) and open `/lab/`.
- Any new visual element must be drawable by `text-raster.js` (or the 3D pass), or it won't show.
