# CLAUDE.md

Effects lab for the ai-workshop site: a sandbox for tuning a "pre-window UI" display layer (low-res emulation, glow, ghosting, scanlines/grid) with live dials. Direction lives in [../docs/aesthetic-direction.md](../docs/aesthetic-direction.md). It's a sandbox: findings feed the real site's design system, and nothing here is final.

## How it works
- The DOM in `index.html` is **invisible** (transparent text). It does layout, selection, copy and find.
- Each frame, `js/text-raster.js` redraws that layout (words, boxes, fills, SVG shapes, selection) into a low-res 2D canvas, using document coordinates measured once per layout change.
- `js/renderer.js` (three.js) composites that canvas plus the 3D object into a low-res buffer, then runs `js/passes/*`: content → ghost → blur → display.
- Effects work in **ink space**: light themes are inverted so ink is always bright on dark, then inverted back in `display.js`.

## File map
- `index.html`: specimen content. `data-ink="phosphor|accent|link|dim|ground"` sets color (`link` is the theme's link colour; CSS `text-decoration: underline` is drawn as a one-emulated-pixel line; selected text is drawn inverted, ink block with ground text) (a CSS `--ink` custom property wins, so `:hover` rules can recolor; `ground` knocks text out of a fill), `data-box` draws a border (honors CSS `border-radius` and `dashed`), `data-fill` a fill (CSS `--fill-alpha` sets its opacity; hidden fills are skipped), `svg[data-draw]` shapes are traced, `[data-graphic="<name>"]` mounts a scene graphic (`js/graphic.js`, scenes in `js/graphics/`), `img[data-draw]` images are stretched to their box and tinted with their ink, `data-tab` draws the notched Figma tab outline sized to the element (CSS `--line`, `--tab-header`, `--tab-flap` for where the notch ends, and `--tab-fill` to fill the header strip), and anything inside `data-clip` is drawn clipped to that element.
- `layout.html` + `css/layout.css` + `js/layout.js`: site layout test from the Figma frames "ref1" (home, node 313:125) and "ref2" (section view, node 313:148). The intro and tabs are an accordion: scrolling scrubs between them and snaps to a whole section; clicks, keys and the URL hash (`#foundations` etc.) animate straight there. Tab headers invert on hover/focus. The page is a canvas 1080 units tall scaled to the screen height (`--u` = screen px per unit, width clamped to 1440–1920 units); every length is in units, and the 12-column grid lives inside each box (`--box-inset`, `--col`, `--span-N`, `.site-grid`). Decisions are in [../docs/design-system/layout-grid.md](../docs/design-system/layout-grid.md). The bottom bar's Grid toggle shows the columns at 25% of the phosphor ink (remembered in localStorage). Pages fire `lab:layout` on `window` to force a re-measure when layout changes without a resize (here, every animation frame). `<body data-preset="light">` loads that preset on every load; `data-panel-id` keeps its dial values separate from the specimen's. Type is fixed in CSS: Chakra Petch in the settled roles, with `@font-face` rules pointing at `../assets/fonts/` (shared with the hierarchy and type pages). The Type dials don't apply here. `<body data-viewer>` turns on the viewer controls: "Press [c] for controls" in the bottom bar opens a 384-unit panel that pushes the panels left (`--controls-open` and `--controls-push`; `--col` follows `--box-w`). It holds palette, motion and blur, specified in [../docs/design-system/palettes.md](../docs/design-system/palettes.md). `<body data-canvas>` makes `js/main.js` treat pixelScale as units (snapped down to 1/2/4/8) and count lines in emulated pixels: the Outline dial sets `--line` (bars and tab outlines) and `--line-dashed` is one emulated pixel. Graphic slots have no frame (it was a wireframe element).
- `type.html` + `css/type.css` + `js/type.js`: typeface specimen on the same canvas as `layout.html` (it reuses `css/layout.css`). `body[data-type]` picks a candidate, switched with keys 1–5, the bottom-bar buttons or the URL hash (`#saira-wide`, `#saira`, `#michroma-oxanium`, `#chakra`, `#michroma-chakra`) and remembered in localStorage. The rejected candidate fonts are local OFL files in `fonts/`, while Chakra Petch and JetBrains Mono come from `../assets/fonts/`. The raster honours `font-stretch` by mapping it to a canvas keyword (see [../docs/design-system/typography.md](../docs/design-system/typography.md)).
- `hierarchy.html` + `css/hierarchy.css` + `js/hierarchy.js`: type hierarchy test in Chakra Petch on the same canvas. The six roles (display, headline, statement, body, label with bar text, code) read `--r-<role>-size/-lh/-wt`, set by a second dial panel, "Type scale" (sizes limited to the spacing scale, line-heights in steps of 4). The panel's "Copy spec" copies the current values. Keys 1–4 load the presets: statement-led, tight leading, the user's tuned spec, and that spec snapped to 8, and I/S (or `#intro`/`#section`) switch between the intro and open-section views. The bottom bar shows the live spec.
- `js/shade.js`: the shading engine for code-drawn graphics. It holds the patterns (hatching, ordered and noise dither), a convex-polygon raster with per-face pattern coordinates, the iso exploded-stack object, the drag `Spin` spring, and `ISO_STYLE`, the look tuned on the shading test (hatch density mode: 4-pixel lines every 24, 12 and 8 pixels, about 17/33/50% ink, then solid; 45°, spacing 8, width 4, 5 steps, solid top step, face-anchored, silhouette 6 grown outward plus face edges 4 centred, so the outline reads as 8 emulated pixels, ink = shadow). `js/graphic.js` builds on it.
- `js/graphic.js` + `js/graphics/*.js`: the scene engine. A scene is JS data: `kind` (`iso` or `flat`), `size` in units (centred in its element, never scaled), iso `parts` (boxes with `explode` offsets, `origin`, `scale`) or flat `shapes` (rect, circle, convex polygon; `fill` none / solid / hatch step 1–3; `outline` outer / inner / none; `part` groups them), `connectors` (2-pixel, `dashed`, `end: "arrow"`, points in units or `{ part, point }` on an iso part), `labels` (DOM text in the label role at `at`, `side`, with a cased leader from `anchor` ending in a square dot; on an iso part, `anchor: { part }` lands on its most visible face, found from the raster, and `{ part, point }` pins it by hand; captions on a side align to its outermost `at` x, or to `labelColumns: { left, right }`; `hover: true` shows the label when the pointer is over its part) and `states` (`explode`, `focus` (accent), `show`, `labels`, `flow` (packets on connectors), `loop: "blink"`, `duration` 400 or 800). ← and → (`stepGraphics` from `layout.js`) step every graphic on screen with an ease-in-out tween. Rapid presses skip to the end state, and motion off (`setMotion`, from the viewer) cuts transitions, stops loops and snaps the drag back. Iso scenes drag to rotate, but not during a transition. Register a new scene in `js/graphics/index.js`. On `layout.html`: `exploded-stack` in the intro, `page-layout` in Foundations.
- `shading.html` + `css/shading.css` + `js/shading.js`: shading test, dither vs hatching side by side (graphics grilling session). It uses `js/shade.js`. Standalone: its own two-colour low-res canvas (palette ground + ink from `presets/palettes.json`), not the raster or display passes. Each column has a step ramp, a flat diagram and an isometric exploded stack (software-projected, drag to rotate, critically damped spring back to the iso pose). The "Shading" dial panel (persisted, id `lab-shading`) sets palette, emulated pixel, pattern anchor (faces or screen), edges, what ink means (shadow or light, auto by ground), light direction, the dither pattern (Bayer 2/4/8, halftone, line screen, white/blue noise, interleaved gradient, Floyd–Steinberg, Atkinson) and scale, the hatching mode (coverage, density, cross, weight), angle, spacing and width, and each side's steps and lightest/darkest range.
- `css/text-layer.css`: layout of the invisible DOM; type sizes are CSS variables set from the dials.
- `js/params.js`: **all** dial definitions and defaults (including `warp`, the rolling CRT/tape wave applied in `passes/display.js`). Add new parameters here first.
- `js/panel.js`: dialkit panel and preset actions. `js/scroll.js`: snapped render offset and scroll velocity.
- `js/viewer.js`: viewer controls state (palette choice, motion, blur), remembered in localStorage. Motion and blur are applied as render overrides by `applyViewer()` in `main.js`. Only pages with `data-viewer` are affected.
- `js/palette-panel.js` + `presets/palettes.json`: the "Palette" dial panel on viewer pages. It edits the active palette (ground, ink, accent, link, ghost 1–3; light or dark follows the ground via `modeOf()`), writes it into the effects dials (theme `phosphor` = ink) once the pinned preset has loaded (`kit.ready`), and its "Save palettes" action writes `presets/palettes.json`.
- `js/main.js`: frame loop.
- `presets/*.json`: named presets (partial values are fine). Add the file name to `presets.file` options in `js/params.js`. The panel's "Save to preset" overwrites the selected preset file with the current dials (needs `serve.py`, which accepts that PUT from this machine only).
- `vendor/dialkit/`: vendored dialkit 2.1.0 (plain-JS build). three.js loads from jsdelivr via the import map.

## Conventions
- Plain HTML + ES modules, no build step. Serve the repo root with `python3 serve.py` (port 8123, no browser caching) and open `/lab/`.
- Any new visual element must be drawable by `text-raster.js` (or the 3D pass), or it won't show.
