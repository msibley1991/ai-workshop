LLM (Large Language Model)

An LLM is a type of AI system that is trained on a very large quantity of text. An LLM reads text and writes text. It calculates which token is most probable as the next token. Chat assistants and coding agents use an LLM.

Model

A model is the specific AI system with it’s particular training data and parameters. Each model has a name and a version, for example Claude Opus 5.5. A provider makes the model. An application, for example a chat assistant, uses the model. Different models have different speed, cost and quality.

Local model

A local model operates on your own computer, not on the server of a provider. Your data does not go to the internet. Usually, local models are smaller and less capable than large online models. You must have a powerful computer with a large memory. Ollama and LM Studio are examples of applications for local models.

Token

A token is a small unit of text that a model reads and writes. A token can be a full word, a part of a word or a punctuation mark. In English, one token is approximately three quarters of a word. Providers calculate the cost of use and the size of the context window in tokens.

Chat assistant

A chat assistant is an application where you talk to a model in a conversation. You write a message, and the model writes a response. Examples are Claude, ChatGPT and Gemini. Usually, a chat assistant does not change files on your computer. It gives you text, code or images, and you use them.

Coding agent

A coding agent is an application that uses a model to write and change code in your project. The agent reads your files, writes code, starts commands and examines the results. It does these steps again and again until the task is complete. You give the task, and you approve important actions. Examples are Claude Code, Codex and Cursor.

Vibe coding

Vibe coding is a method of making software with an AI agent. You tell the agent what you want in natural language, and the agent writes the code. You examine the result, but you do not read or check the code. Andrej Karpathy used the term first in 2025. Vibe coding is fast and good for prototypes. It is not safe for production software, because nobody checks the code.

Prompt

A prompt is the text that you give to a model. The model reads the prompt and writes a response. A prompt can be a question, an instruction or an example. A clear prompt gives a better result. The application also gives the model a system prompt. Usually, you do not see the system prompt.

Prompt engineering

Prompt engineering is the method of writing prompts that give good results. A good prompt tells the model the task, the necessary information, the format of the result and the limits. Examples of good results also help the model. Prompt engineering is about one prompt. Context engineering (see below) is about all the information that the model reads.

Context

Context is all the information that the model has when it writes a response. Context includes the system prompt, the conversation, files, rules and the results from tools. The model does not know other information about your project. If information is not in the context, the model cannot use it.

Context engineering

Context engineering is the design and maintenance of the information that an agent reads. This information includes rules, skills, references and examples, usually in a folder of Markdown files. Good context engineering gives the agent the correct information for each task, and no unnecessary information. Different tools use different names for this folder, for example knowledge base, memory bank or steering files.

Context window

The context window is the maximum quantity of context that a model can read at one time. The unit of measurement is the token. When a conversation becomes too long, the application removes or shortens old information. Then the model does not have the earlier instructions.

Rules

Rules are instructions that you write in a file in your project, for example CLAUDE.md or AGENTS.md. The coding agent reads this file automatically at the start of each session. Use rules to tell the agent about your project, your design system and your preferred method of work. Then you do not write the same instructions again.

Skill

A skill is a folder with instructions and resources for one type of task. Each skill contains a SKILL.md file. An agent reads a skill only when the skill is necessary for the task. This keeps the context small. For example, a skill can tell an agent how to make a slide deck in your design style.

Design system

A design system is a set of rules and reusable parts that keeps the visual design of a product consistent. The rules include colour, typography, spacing and components. In LLM-assisted development, the design system is also written in a format that a model can read, for example Markdown or JSON files. The agent reads these files as context. Then the agent uses the design tokens and components of the design system, and it does not invent its own values. Without a design system, each screen that the agent makes can look a little different.

Design token

A design token is a name for one design decision, for example a colour, a font size or a space. The token connects the name to a value, for example color-primary = #1A73E8. Designers and developers use the name, not the value. If you change the value of a token, all the parts that use the token change. An agent that uses tokens writes code that agrees with the design system. Figma variables can keep design tokens, and an agent can read them through MCP.

CLI / TUI

A CLI (Command Line Interface) is a text interface. You type a command, and the computer shows the result as text. A TUI (Text User Interface) also operates in a terminal. But a TUI shows menus, panels and other visual parts with text characters. Many coding agents are TUI applications.

IDE (Integrated Development Environment)

An IDE is an application for writing code. It contains a code editor, a file browser, a terminal and tools that find errors. Examples are VS Code and Cursor. Many IDEs contain an AI assistant.

Markdown

Markdown is a simple format for text files. Markdown uses symbols to show structure, for example # for a heading and * for a list item. Markdown files have the extension .md. People and models can read Markdown easily. For this reason, people frequently write prompts, rules and skills in Markdown.

Obsidian

Obsidian is an application that you use to write and arrange notes. Obsidian keeps each note as a Markdown file in a folder on your computer. Obsidian calls this folder a vault. You can link a note to other notes and see all the links as a graph. Because the notes are Markdown files, a coding agent can read and change them. For this reason, some people use Obsidian to write and keep the rules, skills and references for context engineering.

MCP (Model Context Protocol)

MCP is a standard that connects AI applications to other tools and data. An MCP server gives a model access to a tool, for example Figma, GitHub or a database. With MCP, a model can read data from the tool and do tasks in the tool. Anthropic made MCP. Now many companies use it.

Git

Git is a version control system. Git keeps a record of all changes to the files in a project. Each saved set of changes is a commit. With Git, you can compare versions, go back to an earlier version and work on different versions (branches) at the same time. Git operates on your computer.

GitHub

GitHub is a website that keeps Git repositories online. Teams use GitHub to share code, examine changes and work together. GitHub is not Git. Git is the tool. GitHub is one service that uses Git. Other services are GitLab and Bitbucket.

Package manager

A package manager is a tool that installs and updates packages. A package is code that other persons wrote and that you can use in your project. The packages that your project uses are its dependencies. The package manager finds the correct versions and keeps a list of them in a file. Examples are npm for JavaScript and pip for Python. You operate a package manager from the CLI, for example with the command npm install.
